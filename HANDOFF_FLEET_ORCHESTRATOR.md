## 1. System Context & Architecture Overview

`Fleet-Orchestrator` is the **computational workhorse, multi-account credential aggregator, and headless queue worker engine** for the ecosystem. It manages 27 verified GitHub Copilot CLI accounts pooling **5,400 monthly AI credits** ($27 \times 200$), executing code implementation tasks generated by Claude Desktop.

### Key Architectural Shift:
- **Decoupled File-Watching Worker**: Lightweight, resilient background worker (`tools/copilot_queue_worker.py`) that monitors `orchestrator-state/tasks/` for `kind == "code"` and `status == "pending"`.
- **Round-Robin Account Rotation with Cooldown Governance**: Automatically distributes code jobs across all ready Copilot workers in `.env.fleet` (`copilot-w1` through `copilot-w27`), dynamically bypassing accounts in active rate-limit or monthly quota cooldown.
- **Provider Auto-Routing Enforcement**: Strictly omits `--model` flags on Copilot Free accounts to prevent quota exhaustion errors and comply with GitHub's model routing constraints.
- **Automated Worktree Isolation**: Auto-provisions and tears down isolated Git worktrees for zero file collisions between concurrent or sequential task executions.

## 2. Current State & Assets in `Fleet-Orchestrator`

1. **`tools/copilot_queue_worker.py`**:
   - Discovers state directory (`orchestrator-state`) via CLI `--state-dir`, environment, or auto-detection.
   - Discovers active accounts from `.env.fleet` via `discover_accounts()`.
   - Auto-provisions isolated Git worktrees (`git worktree add -b task/<task_id> <worktree_dir> HEAD`).
   - Automatically commits changes (`feat({task_id}): automated implementation`) and cleans up worktrees upon checkpoint submission or failure.
   - Parses `--usage-output-file` JSON from `copilot.exe` for `credits_used`, `tokens_used`, and quota exhaustion detection.
   - Dynamically tracks credit usage per account, persisting telemetry (`credits_used`, `credits_remaining`, `monthly_credits`, `cooldown_until`) into `live-status/<worker_id>.json`.
   - Transitions exhausted accounts to `cooldown` state, skipping them during round-robin selection.
   - Atomic file claiming via `os.replace` preventing multi-process race conditions.
   - Supports both multi-process concurrency and in-process concurrency (`--concurrency N`), `--worker-id` binding, `--once`, `--dry-run`, and `--no-worktree`.

2. **One-Click Runner**:
   - `launch_copilot_worker.bat`: Starts the background queue worker instantly in a minimized terminal (~14 MB RAM) with CLI argument pass-through (`%*`).

3. **`client/adapters/copilot_cli_adapter.py`**:
   - Subprocess wrapper around local `copilot.exe` (`-p`, `--autopilot`, `--allow-all`, `--no-ask-user`, `--worktree`, `--usage-output-file`).
   - Telemetry extraction for credits, tokens, and model, plus explicit quota exhaustion detection.
   - Sub-process environment isolation (`COPILOT_GITHUB_TOKEN`, `COPILOT_HOME`).

4. **Coordination & Scheduling Core**:
   - `server/core/scheduler.py`: Quota-aware scheduler with stage affinity weights (`+0.2` for code/draft on Copilot CLI, `+0.2` for plan/QA on Claude).
   - `client/scratchpad_manager.py`: Thread-safe markdown scratchpad manager for multi-worker chaining.
   - `sku-templates/claude_copilot_hybrid_cycle.json`: Stage pipeline template for `plan -> code -> qa_review`.

5. **Test Suite Status**:
   - **152 / 152 tests passing** (100% pass rate in `pytest` including `tests/test_copilot_queue_worker.py`, `tests/test_copilot_cli_adapter.py`, `tests/test_claude_copilot_hybrid.py`, `tests/test_claude_fleet_supervisor.py`, and `tests/test_scratchpad_manager.py`).
