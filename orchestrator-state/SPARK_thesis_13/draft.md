## Mid Defense: implementation, results, limitations, and remaining work

### Completed implementation

The completed, evidence-backed implementation is an offline human-fall classification workflow using the SisFall dataset. Its processed input consists of 200 time samples and six IMU channels at 100 Hz, representing a two-second window. The preparation pipeline resamples native 200 Hz recordings to 100 Hz and constructs the 200-sample windows; training loads the resulting `(N, 200, 6)` input shape (`training/data_prep/prepare_sisfall.py:8-14,26-32,56-57,95-107,116-125`; `training/train_cnn.py:65-68`). The processed corpus inventory contains 38,426 windows, but that total is not the denominator of the archived held-out evaluation (`data/README.md:16-19,35`; `data/processed_sisfall/model/test_report.txt:3-4`).

The repository contains a 1D CNN training implementation, saved Keras and INT8 TFLite model artifacts, configuration and evaluation reports, and a firmware-facing input interface for 200 samples × 6 channels (`training/train_cnn.py:242-257`; `data/processed_sisfall/model/model_config.json:1-10`; `data/processed_sisfall/model/quantization_report.txt:4-23`; `firmware/main/tflite/inference.h:21-23,35-36`). The training code uses subject-grouped splits and checks that subject groups do not overlap; it describes a single holdout procedure, not cross-validation (`training/train_cnn.py:87-114`).

These are completed software and offline-model artifacts. They should not be described as a completed wearable or deployed fall-detection system: the MPU6050 driver returns a zeroed sample without real I²C acquisition, the inference path returns fixed 0.5/0.5 probabilities rather than invoking a TFLite Micro model, and the application/logger paths do not demonstrate continuous sensing (`firmware/main/drivers/mpu6050.cpp:1-31`; `firmware/main/tflite/inference.cpp:1-38`; `firmware/main/app_main.cpp:25-45,60-75`).

### Results

The archived held-out SisFall report records 6,712 test windows—1,575 FALL and 5,137 NON_FALL—from eight test subjects. At the report's validation-selected Youden threshold of 0.3919, it gives sensitivity 0.8781, specificity 0.7818, and AUC 0.9185 (`data/processed_sisfall/model/test_report.txt:3-12`). These are saved artifact results, not measurements independently reproduced for this chapter. The reported sensitivity is below the stated 90% target.

A separate quantization report records INT8 sensitivity 0.8743, specificity 0.7014, AUC 0.8717, and an 18,904-byte TFLite model on its reported 6,712-window test set (`data/processed_sisfall/model/quantization_report.txt:4-6,13,24-33`). The report's model-file size is not a measurement of total firmware flash use, and these INT8 metrics should not be conflated with the separate held-out report's FP32 figures.

The saved Colab log is another run/output, not a replacement for or continuation that can be combined with the archived report: it records corpus size 38,426 and split counts 31,714/3,005/3,707, then reports sensitivity 0.8981, specificity 0.7621, and AUC 0.9272 at threshold 0.4236 (`training/colab_run_output.txt:39-45,145-159`). Those scores remain below 90% sensitivity. The Colab log's test count and threshold differ from the 6,712-window report and the threshold 0.4065 recorded in `model_config.json` and the checked-in C header (`training/colab_run_output.txt:39-41,145-147`; `data/processed_sisfall/model/model_config.json:3,22-26`; `firmware/main/models/spark_cnn_int8.h:2-3,1587`). Until run, split, threshold, and binary provenance are reconciled, these results must remain separately attributed.

### Limitations

The available evidence supports offline SisFall evaluation only, not clinical, cohort, or real-world wearable validation. The exact held-out subject IDs, full split/seed provenance, and immutable artifact identity for each reported result remain unresolved (`data/processed_sisfall/model/test_report.txt:3-4`; `training/train_cnn.py:87-114`). The full-corpus inventory must not be presented as the evaluation denominator.

There is a consequential sampling/windowing discrepancy in project materials. The executable SisFall preprocessing produces 100 Hz, 200-sample (two-second) inputs, whereas some architecture or thesis prose describes a 200 Hz logger and/or a three-second window. A three-second 200 Hz window would contain 600 samples, not the model's 200; the planned 200 Hz logger must therefore be treated as a separate acquisition path, not the evaluated model input (`training/data_prep/prepare_sisfall.py:8-14,26-32,56-57,116-125`; `AGENT.md:11`; `docs/SPARK_Proposal/Chapters/chapter5_methodology.tex:198`).

The checked-in header declares 18,912 embedded bytes and threshold 0.4065, while the available TFLite FlatBuffer is 18,904 bytes and does not match the header's embedded bytes. The claimed matching upgraded FlatBuffer was not present in the inspected workspace; neither header identity nor model-file size proves device inference (`firmware/main/models/spark_cnn_int8.h:2-3,8,1587`; `data/processed_sisfall/model/quantization_report.txt:6`; delta review, “Accept header size; limit identity assertion”). No physical ESP32-S3 inference or latency result, continuous logger validation, measured power/runtime, or approved/collected Nepal cohort performance is established (`firmware/main/tflite/inference.cpp:1-38`; `firmware/main/drivers/mpu6050.cpp:1-31`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:99,117-123`; `README.md:59,72,159-161`).

Historical OpenVINO timings of 0.131 ms CPU, 0.200 ms GPU, and 0.383 ms NPU over 5,000 INT8 inferences are reported for an Intel Core Ultra 7 155H gateway. They are not raw benchmark artifacts and are not ESP32-S3 latency measurements (`dev_logs/SPARK_TRACKER.md:105-110,482`; `docs/SPARK_Proposal/Chapters/chapter3_related_theory.tex:31-35`). Battery current/runtime figures in project documents are estimates, not measured system results; sources give differing ranges and state that physical power telemetry/profiling has not been done (`docs/SPARK_Proposal/Chapters/chapter5_methodology.tex:77`; `dev_logs/SPARK_TRACKER.md:518-520,841-843`; `docs/SPARK_Proposal/Chapters/chapter3_related_theory.tex:47`; `docs/SPARK_Proposal/Chapters/chapter4_feasibility_study.tex:15`).

## Final Defense: methods, evaluation, discussion, and status

### Methods

This work's evaluated method is offline binary classification of processed SisFall IMU windows for human fall detection. The preprocessing contract resamples source data recorded at 200 Hz to 100 Hz, uses 200 samples per window (two seconds), and represents each sample with six channels; the model input is therefore `(N, 200, 6)` (`training/data_prep/prepare_sisfall.py:8-14,26-32,56-57,95-107,116-125`; `training/train_cnn.py:65-68`). The training code partitions data by subject group using a single train/validation/test holdout and asserts disjoint subject sets (`training/train_cnn.py:87-114`). It is not cross-validation. The archived report says the held-out set contains 6,712 windows from eight subjects but does not provide the subject IDs in the reported lines; reproducibility of the precise split should therefore not be overstated (`data/processed_sisfall/model/test_report.txt:3-4`).

The repository also contains an INT8 quantization report for a separate reported evaluation, including input `[1,200,6]`, output `[1,2]`, model size, and quantized metrics (`data/processed_sisfall/model/quantization_report.txt:4-33`). Treat the report as stored evidence; no notebook or training run was repeated for this account.

### Evaluation

The archived held-out report's validation-selected threshold is 0.3919. It reports sensitivity 0.8781, specificity 0.7818, and AUC 0.9185 over 6,712 test windows (1,575 FALL, 5,137 NON_FALL) from eight subjects (`data/processed_sisfall/model/test_report.txt:3-12`). The separately reported INT8 result is sensitivity 0.8743, specificity 0.7014, and AUC 0.8717, with an 18,904-byte model and the same stated test-set size (`data/processed_sisfall/model/quantization_report.txt:4-6,13,24-33`). Both are saved artifact results and both sensitivities are below the stated 90% target.

The later saved Colab output reports a different partition (31,714/3,005/3,707), threshold 0.4236, sensitivity 0.8981, specificity 0.7621, and AUC 0.9272 (`training/colab_run_output.txt:39-45,145-159`). This is a historical reported run output, not a reconciled result with the archived 6,712-window evaluation. A further configuration/header threshold of 0.4065 does not match either the Colab log's 0.4236 or the archived report's 0.3919 (`data/processed_sisfall/model/model_config.json:3,22-26`; `firmware/main/models/spark_cnn_int8.h:2-3,1587`; `data/processed_sisfall/model/test_report.txt:5`; `training/colab_run_output.txt:145-147`). Accordingly, no single “final” score, threshold, or deployable model should be asserted until the respective model, split, and threshold provenance is reconciled.

### Discussion and limitations

The stored evidence demonstrates that the project has an offline SisFall training and evaluation workflow and compact quantized model artifacts. It does not establish that the 90% sensitivity target was met, that the result generalizes to a Nepalese cohort, or that the model operates on a wearable. The corpus count of 38,426 describes processed data inventory; the archived evaluation denominator is 6,712, while the later log reports a distinct 3,707-window test partition (`data/README.md:16-19,35`; `data/processed_sisfall/model/test_report.txt:3-4`; `training/colab_run_output.txt:39-41`).

Input shape alone does not resolve the sampling contract: the implemented SisFall pipeline uses 100 Hz and two-second windows, whereas 200 Hz appears in descriptions of a planned logger and conflicting window-duration text. Those paths need explicit, separate preprocessing specifications and compatible model input before hardware evaluation (`training/data_prep/prepare_sisfall.py:8-14,26-32,116-125`; `AGENT.md:11`; `docs/SPARK_Proposal/Chapters/chapter5_methodology.tex:198`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:14`). Likewise, stored laptop OpenVINO timings are historical gateway reports, not embedded timing, while battery values remain estimates (`dev_logs/SPARK_TRACKER.md:105-110,482,518-520,841-843`; `docs/SPARK_Proposal/Chapters/chapter3_related_theory.tex:31-35,47`).

The firmware evidence is scaffolding rather than an integrated inference demonstration: sensor reads are zeroed, inference probabilities are fixed, and the application/logger path does not show continuous real-sensor windows or a linked TFLite Micro execution (`firmware/main/drivers/mpu6050.cpp:1-31`; `firmware/main/tflite/inference.cpp:1-38`; `firmware/main/app_main.cpp:25-45,60-75`). Physical hardware bring-up, device-level latency and power measurement, institutional approval, and Nepal cohort data/results are not established in the reviewed sources (`README.md:59,72,159-161`; `AGENT.md:3`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:99,117-123`). The saved work should therefore be characterized as offline SisFall evaluation—not clinical, real-world, or hardware validation.
