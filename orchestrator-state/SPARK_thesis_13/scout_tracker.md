# SPARK thesis scout tracker — evaluation and claim audit

**Scope:** Read-only review of the requested SPARK tracker, plans, team briefings, thesis source, and available result artifacts. SPARK was on the expected branch, `docs/next-semester-thesis-roadmap-#13`; the existing untracked `docs/SPARK_Final_Defense/` and `docs/SPARK_Mid_Defense/` directories were left untouched.

The proposal title page names the project **“SPARK: Explainable Edge AI for Kinetic Pattern Recognition and Distress Signaling”** and authors Aaradhya Dev Tamrakar, Rupesh Kadel, Sankalpa Lamsal, and Sonia Thapa (`docs/SPARK_Proposal/FrontPages/title.tex:6,11-14`). The certificate identifies Er. Dipen Manandhar as Project Supervisor (`docs/SPARK_Proposal/FrontPages/certificate.tex:15-16`). The primary thesis claim should remain **human fall detection**: the tracker explicitly defines elderly-care fall detection as operational scope (`dev_logs/SPARK_TRACKER.md:653`). Robotics is an exploratory extension, not a validated project result (`docs/SPARK_Proposal/Chapters/chapter6_expected_output.tex:50-55`; `docs/SPARK_STRATEGIC_ROADMAP_ROBOTICS_AND_HARDWARE_DEFENSE.md:32-39`). Grounded topic links: [[SPARK]] · [[Human fall detection]].
The current audit notes now explicitly distinguish existing 100 Hz / 2 s SisFall preprocessing from the planned 200 Hz logger, mark driver/TFLite deployment and robotics unvalidated, and warn against combining August and October result generations (`dev_logs/SPARK_TRACKER.md:6`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:14`; `docs/SPARK_STRATEGIC_ROADMAP_ROBOTICS_AND_HARDWARE_DEFENSE.md:12`; `docs/team_briefings/README.md:12`).

## Contradictions and evidence gaps to resolve before thesis claims are refreshed

- **Sampling, window, and overlap mismatch:** The current preprocessing code documents native SisFall recordings at 200 Hz, resampling to 100 Hz, and 200-sample / 2 s windows (`training/data_prep/prepare_sisfall.py:10-11,30-32,57,95-125`). Its default stride equals the window length (non-overlapping) (`training/data_prep/prepare_sisfall.py:11,175-181,189`); the saved model shape `(None, 200, 6)` alone does not encode sample rate (`training/colab_run_output.txt:167`). Thesis methodology instead says 200 Hz, 1.0 s, with 50% overlap during impact intervals (`docs/SPARK_Proposal/Chapters/chapter5_methodology.tex:198`), and older tracker prose says “200Hz 3-second windows at 200 samples/window” (`dev_logs/SPARK_TRACKER.md:350,725`). The current 200 Hz logger is a separate planned path (`dev_logs/SPARK_TRACKER.md:6`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:14`). Align the thesis and scripts to the model-generation preprocessing, and explicitly document any distinct future logger preprocessing.
- **Evaluation denominator/run ambiguity:** Stored test report has 6,712 test windows / 8 subjects (`data/processed_sisfall/model/test_report.txt:3-4`); Colab output has 3,707 test windows (`training/colab_run_output.txt:39-41`). The source reports different thresholds and scores, and the threshold in the later log (0.4236) differs from `model_config.json` (0.4065). Retain separate run labels, test-set definitions, threshold selection, seed/config, and model artifact identity; do not present the figures as a single benchmark.
- **Raw SisFall file counts:** Tracker says 4,500 processed trial files (`dev_logs/SPARK_TRACKER.md:65`) but also describes a 4,506-file archive and five SHA256 duplicates rejected (`dev_logs/SPARK_TRACKER.md:350`); README describes 4,506 dataset files (`data/README.md:34-39`). State raw archive files separately from successfully parsed/unique trials and explain any exclusions.
- **Unmeasured hardware/battery claims:** No collected KEC data or physical logger validation is evidenced; procurement and approvals are explicitly future gates (`dev_logs/SPARK_TRACKER.md:10`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:102-123`). Current, runtime, end-to-end GPIO latency, and “hardware verified” claims need bench artifacts or must be marked planned/estimated. The exact battery values conflict across versions (`dev_logs/SPARK_TRACKER.md:520,843`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:50`; `docs/SPARK_Proposal/Chapters/chapter3_related_theory.tex:47`).
- **Benchmark evidence inventory:** No top-level `report/` or benchmark-named JSON was present. There are stored SisFall report files (`data/processed_sisfall/model/test_report.txt`, `quantization_report.txt`), a saved Colab log, model/config artifacts, and gateway replay JSONs. The gateway JSONs are replay evidence, not performance benchmark records.
- **Status inflation in defense prose:** The strategic roadmap’s faculty pitch claims the ML, firmware emulation, CAD, and UI are “100% complete” (`docs/SPARK_STRATEGIC_ROADMAP_ROBOTICS_AND_HARDWARE_DEFENSE.md:80`). Firmware briefing entries are framed as to-do tasks and acceptance criteria, not passed-result logs (`docs/team_briefings/RUPESH_FIRMWARE_PRE_HARDWARE_GUIDE.md:17-48,54-88`); CAD briefing likewise describes work to perform and measurements to record (`docs/team_briefings/SANKALPA_CAD_ENCLOSURE_GUIDE.md:6,50-60`); the mobile guide says to build and test the app and phone integration (`docs/team_briefings/SONIA_MOBILE_CLIENT_GUIDE.md:6,13,53-57`). Recast that quote as proposed work / status narrative, not verified completion. Team-guide claims of “up to 80%” battery saving and sub-0.05 ms layer-1 timing are not backed by a measurement artifact (`docs/team_briefings/RUPESH_FIRMWARE_PRE_HARDWARE_GUIDE.md:97-101`).
- **Test-count and scope drift:** The proposal/master plan report 48 passing tests (`docs/SPARK_Proposal/Chapters/chapter4_feasibility_study.tex:9,24`; `docs/SPARK_POST_BOARDS_MASTER_PLAN.md:31`), while tracker v57 says 56/56 (`dev_logs/SPARK_TRACKER.md:32`). State the count with its run/date and describe tests as software tests only; neither count establishes physical-hardware verification.
- **Robotics boundary:** The strategic roadmap explores robotics dual-use architecture and explicitly lists hardware-grade IMU, E-stop/CAN/ROS2, and synthetic-training upgrades (`docs/SPARK_STRATEGIC_ROADMAP_ROBOTICS_AND_HARDWARE_DEFENSE.md:20-39`). Thesis chapter 6 labels robotics as future work (`docs/SPARK_Proposal/Chapters/chapter6_expected_output.tex:50-55`). Keep this clearly exploratory; human fall detection remains the thesis evaluation scope.

## Replacement evidence gate sequence

1. **Preparation, no purchase:** reconcile BOM/order package; finish and review the protocol; prepare supervisor/HOD ethics materials (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:96-100`).
2. **Procurement:** place the approved order next semester after Dashain, Tihar, and Chhath; do not assign calendar dates before confirmations (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:6,58,102-104`).
3. **Parts receipt and inspection:** confirm receipt before hardware milestones (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:69-74,104-106`).
4. **Logger validation:** assemble after parts arrive and verify a stable 200 Hz stream and recordings (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:73-74,106-113`).
5. **Approved cohort collection:** begin only when **both** institutional approval and logger validation are complete; the plan requires clearance and validated logger before cohort sessions (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:65,99,117-123`; `dev_logs/SPARK_TRACKER.md:10,389`).
6. **Integrated evaluation:** after cohort data is prepared, run transfer learning, quantization/export, and integrated system validation; keep all results tied to documented subject split, input shape/windowing, threshold, and hardware setup (`docs/SPARK_POST_BOARDS_MASTER_PLAN.md:82-89,127-143`).

**Bottom line:** SisFall/model files and stored evaluation artifacts exist, but their scores differ across saved runs and do not demonstrate the 90% sensitivity target. The Nepal cohort, physical logger/hardware evaluation, and battery measurements remain gated or unmeasured; describe them as planned or estimated until their evidence gates are satisfied.
